# next.js-template

A Next.js 16 App Router starter by [sarcasterXO](https://github.com/sarcasterXO). The public repository is [github.com/sarcasterXO/next.js-template](https://github.com/sarcasterXO/next.js-template). It is a generic template, not a deployed product: there is no database, auth, or static GitHub Pages export. `POST /api/echo` checks a JSON `message` and returns it.

## Stack

- Next.js 16.4 and React 19, App Router at the repo root. No `src/` directory.
- TypeScript 6.0.3. Typecheck with `tsc` through `bun run typecheck`. Do not use `bun check`.
- Bun 1.4.4. `packageManager` is pinned. Install with `bun install`.
- Tailwind CSS 4 through `@tailwindcss/postcss`. There is no `tailwind.config`.
- shadcn style `base-rhea` on Base UI. One component exists: `components/ui/button.tsx`.
- `motion`, `react-icons`, and `three` are installed for later use. Do not add a demo just to import them.
- Zod 4.6.7. `lib/validation.ts` parses JSON for API routes.
- Oxlint and Oxfmt, both extending `@imranbarbhuiya/oxc-config`. Oxlint is type-aware.

## Layout

```
app/layout.tsx          Root layout, Inter, `metadata` and `viewport`
app/page.tsx            Starter home page
app/not-found.tsx       404 page with a link home
app/robots.ts           `/robots.txt`: allow `/`, disallow `/api/`
app/globals.css         Tailwind and shadcn theme tokens
app/favicon.ico         Next.js icon
components/ui/          shadcn components
components.json         shadcn CLI config
lib/utils.ts            Re-exports `cn` from the `cn` package
lib/validation.ts       `parseJson` and `parseInput` for API routes
app/api/echo/route.ts   `POST /api/echo`
next.config.ts          `cacheComponents` and `partialPrefetching` on. No `output: 'export'`
oxlint.config.mts       Lint config
oxfmt.config.mts        Format config
postcss.config.js       Tailwind PostCSS plugin
tsconfig.json           `@/*` maps to the repo root. `incremental` is false
.github/workflows/      GitHub-hosted CI
.github/husky/          commit-msg and pre-commit hooks
.github/problemMatchers tsc problem matcher for CI annotations
.vscode/settings.json   Oxc as formatter and fixer, workspace TypeScript
.vscode/extensions.json Recommends the Oxc and Tailwind CSS extensions
```

`next build` writes `.next`. `next-env.d.ts` is generated by `next typegen` and ignored by git. Do not turn incremental compilation back on. That writes `tsconfig.tsbuildinfo`.

The home page is a centered starter: edit `app/page.tsx`, then Deploy Now or Documentation. It links to the template repository. The theme is light and muted. `color-scheme` is `light`. Do not add a dark-mode toggle.

`cacheComponents` is on. A component that reads uncached or request-time data (`fetch`, `cookies()`, `headers()`, `searchParams`, `params`) must sit inside `<Suspense>` or use `'use cache'`. Read `node_modules/next/dist/docs/01-app/01-getting-started/08-caching.md` before adding data fetching. `partialPrefetching` is on, so `<Link>` prefetches the route's App Shell by default.

`app/layout.tsx` sets `title.template` to `%s | next.js-template`, so a page exports `title: 'Name'`, not the full title. `name` and `description` constants feed `metadata`, `openGraph`, and `twitter`. There is no `metadataBase`, no Open Graph image, and no sitemap. `app/robots.ts` has no `sitemap` or `host` because there is no site URL. Add them with `metadataBase`. Add `metadataBase` before using relative URLs in metadata, or the build fails. `viewport.themeColor` is `#e5ecf3`, the hex of `--background`. Change both together.

Buttons that render an `<a>` must set `nativeButton={false}`. Internal links use `render={<Link href="/" />}`, as in `app/not-found.tsx`. Base UI otherwise warns that it expected a `<button>`.

## Commands

- `bun run dev` starts the app.
- `bun run preflight` formats, typechecks, lints with fixes, and builds.
- `bun run lint:check` and `bun run format:check` report without writing.
- `bun run build` then `bun run start` serves the production build.

CI on GitHub-hosted `ubuntu-latest` runs `lint:check`, `format:check`, and `typecheck` for pushes to `main` and for pull requests. There is no deploy workflow. CI does not run commitlint; only the local `commit-msg` hook does. CI does not run `next build`, so run `bun run build` locally before pushing changes that touch rendering or config.

## Conventions

- Add shadcn components with `bunx shadcn add <name>`. `components.json` sets `iconLibrary` to `lucide` so the CLI stays valid. `lucide-react` is not installed. Use `react-icons`. If a generated file imports `lucide-react`, replace that import and remove the package.
- Oxlint sorts JSX props alphabetically. `className` comes before `lang` and before `data-slot`.
- Commit messages follow Conventional Commits. The `commit-msg` hook runs commitlint.
- The `pre-commit` hook runs lint-staged: Oxfmt on staged files, then Oxlint `--fix` on staged JavaScript and TypeScript, including `jsx` and `tsx`.
- `plans/` is historical, gitignored, and ignored by Oxlint and Oxfmt. Fresh clones do not have it. Do not restyle it while changing the template.
- API routes live at `app/api/<name>/route.ts`. Schemas live in that file. `lib/validation.ts` stays helpers only, and a schema moves there only when two routes share it.
- `parseJson(request, schema)` reads a JSON body. Invalid JSON returns `{ ok: false, formErrors: ['Expected a JSON body'], fieldErrors: {} }`. It does not read query strings. A caller with a query object passes that object to `parseInput`.
- `parseInput(schema, value)` uses `z.flattenError`. Failures are `{ ok: false, formErrors, fieldErrors }`. Field errors are one level deep.
- A route returns `Response.json(result, { status: 400 })` when the body fails, and `Response.json(result, { status: 500 })` when the payload fails its response schema. Success is `Response.json(result.data)` (HTTP 200).
- `POST /api/echo` expects `{ "message": "<non-empty string>" }` and returns `{ "message": "<same string>" }`.
